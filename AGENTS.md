# Project Agent Rules — AI YouTube Studio

## 1. Mandatory Post-Task Workflow: Auto-Optimize, Merge & Push (`auto-optimize-merge-push`)
- Whenever you complete any code modification, bugfix, refactoring, or configuration update in `d:\AI_YouTube_Project_Ready\AI-youtube-main` (or `d:\Python\Youtube`), you **MUST** automatically follow the [auto-optimize-merge-push](.agents/skills/auto-optimize-merge-push/SKILL.md) skill before finishing your turn:
  1. **Optimize & Verify**: Clean up dead code/imports, ensure backward-compatible method signatures, and verify all modified Python files using `python -m py_compile` plus a quick import/smoke test.
  2. **Safe Sync & Merge**: Ensure all changes are merged cleanly onto the `main` branch without conflicts (excluding secrets, `.env`, `.db`, `*.pickle`, and runtime outputs).
  3. **Auto Commit & Push**: Stage modified files (`git add`), commit with a clear Conventional Commit message (`feat/fix/perf/refactor`), and push directly to GitHub (`git push origin main`) without waiting for the user to ask.

## 2. Periodic 14-Day System, Agent & Model Upgrade Check (`biweekly-system-model-upgrader`)
- Every **2 weeks (14 days)** — tracked via [d:\AI_YouTube_Project_Ready\.agents\last_system_audit.json](../.agents/last_system_audit.json) — or whenever requested by the user, follow the [biweekly-system-model-upgrader](.agents/skills/biweekly-system-model-upgrader/SKILL.md) skill:

  2. **Mandatory Report-Before-Execute Gate (Báo cáo trước khi thực hiện)**: **NEVER** apply model/technology upgrades silently. Always present a detailed comparison report in Vietnamese to the user first and wait for confirmation before executing changes.

## 3. Mandatory 100% Real YouTube Metrics Reporting & Viral Ceiling-Breaker Strategy (`youtube-real-metrics-reporting` & `youtube-viral-ceiling-breaker-strategy`)
- Whenever the user asks for a summary, status check, or performance analysis of uploaded YouTube videos or channels, you **MUST** follow the [youtube-real-metrics-reporting](.agents/skills/youtube-real-metrics-reporting/SKILL.md) skill:
  1. **Zero Estimation Policy**: **NEVER** report estimated/interpolated retention metrics (`APV %`, `Stayed %`, `Swipe Away %`, `AVD`). Only report 100% real numbers fetched from **YouTube Data API v3** and **YouTube Analytics API v2** (or user-provided YouTube Studio Realtime screenshots). If a video is `< 24–48h` old and YouTube Analytics API v2 has not finalized its row yet, explicitly display `⏳ Chờ Analytics chốt sổ (24–48h)`.
  2. **Mandatory Strategic Analysis**: Always accompany the real data tables with a data-driven analysis covering top-performing videos (velocity, `Like/View %`, real `APV %` / `Stayed %`), recovering channels, and actionable warnings based strictly on real metrics.
- Whenever you ideate topics, write/review titles and scripts, curate visuals, or diagnose why videos break or hit the `1.2K–1.8K` view ceiling, you **MUST** follow the [youtube-viral-ceiling-breaker-strategy](.agents/skills/youtube-viral-ceiling-breaker-strategy/SKILL.md) skill:
  1. **Rule 1 — Never Hide the Primary Entity in Titles (`YT_SEARCH` Re-ignition Engine)**: Always name the exact, high-search-volume entities (`[Entity A] vs [Entity B]: [Extreme Physical Metric]`, e.g., *Lula-Colossal vs Cachalote: 2.000m*, *Onça-Pintada vs Jacaré: 1.500 PSI*). **NEVER** hide the entity behind vague curiosity gaps (*"This 4,000lb Giant"*, *"This Beast"*, *"Mordida de 1.100 PSI"* without naming the animal), which kills `YT_SEARCH` discovery after Day 1.
  2. **Rule 2 — Preserve Deep `34s–40s` 5-Act Dual-Peak Scripts + `>= 80%` Real Moving Video Clips (Pass the Day-2 Broad Cohort Test)**: Never truncate scripts below `30s` in a way that makes the narrative shallow. Use two-way escalation (*Entity A's weapon* -> *Entity B's counter-mechanism twist at Scene 4–5*) and interleave real moving video clips (`>= 80%` video scenes, `hook_frame_sharpness >= 12.0`) throughout the body so `Stayed %` and `APV %` hold or increase on Day 2 when YouTube expands to broad audiences.
  3. **Rule 3 — US Geo-Routing Schedule Law (NEVER Schedule English `US` Channels at `13:00–16:30 UTC` / `20:00–23:30 VN` Bedtime Peak)**: Publishing English (`US`) channels at `14:30–15:30 UTC` (`21:30–22:30 VN`) hits Vietnam's prime bedtime scrolling window, causing YouTube to seed `52%–68%` of initial traffic to Vietnam (`APV = 42.9%–55.2%`) instead of the US (`APV = 80.9%–148.3%`). **100% of English (`US`) channel uploads MUST be scheduled strictly inside `17:30–21:45 UTC` (`00:30–04:45 AM VN` deep-sleep window: Slot 1 = `18:00 UTC` / `01:00 AM VN` and Slot 2 = `21:00 UTC` / `04:00 AM VN`, `MIN_SPACING_SECONDS = 10800`).** Only `pt-BR` Brazil channels (`Odisseia Selvagem`, `Mistérios do Mundo`) may use `13:30–14:15 UTC` (`10:30–11:15 AM BRT` Brazil Lunch Peak).
  4. **Rule 4 — Anti-Collision, Comment Backfill & `50%` Auto-Thumbnail Hero-Frame Law**:
     - **Anti-Collision**: NEVER schedule a Long-Form (`16:9`) video and a Short (`9:16`) at the same timestamp on the same channel (enforce `>= 3.0 hours` / `10,800s` spacing).
     - **Comment Backfill**: Because YouTube Data API v3 blocks `commentThreads().insert` while a video is `private`/`scheduled`, always run `sync_channel_pinned_comments` / `ensure_pinned_comment` once scheduled videos go `public` so no public video stays at `0` comments. Lock `categoryId` to `'15'` (Wildlife/Pets) or `'22'` (Mysteries/History/Psychology) — NEVER `'27'` (`Education`).
     - **`50%` Midpoint Auto-Thumbnail Law (Unverified Channels)**: YouTube ALWAYS uses `2.jpg` (**the exact `50.0%` midpoint**) as `hqdefault.jpg` (`1.jpg` = `25%`, `3.jpg` = `75%`). Never stamp thumbnail text at `0.0s–0.5s`; for `16:9` Long-Form videos, always lock the sharpest close-up Hero Clip + a dark lower-third bar + Giant `88px` Two-Tone Banner (`Alignment=2`, `MarginV=48`) at `25%`, `50%`, and `75%`, and keep `16:9` titles `< 55–60 chars`.

## 4. Mandatory System-Wide Root-Cause Bugfix & Anti-Overfitting (`systemic-root-cause-bugfix`)
- Whenever you debug, fix, or optimize any issue in the project, you **MUST** follow the [systemic-root-cause-bugfix](.agents/skills/systemic-root-cause-bugfix/SKILL.md) skill (incorporating GitHub's `obra/superpowers` `systematic-debugging`, `root-cause-tracing`, `defense-in-depth`, and Anti-Reward-Hacking guardrails):
  1. **Zero Test-Case Overfitting & Zero Keyword-Patching Policy**: **NEVER** patch bugs by hardcoding topic/species/biome/weather keyword lists (`if "snow" in ...`, `if "tiger" in ...`, etc.) or blindly appending static strings to queries just to pass a single test case. Every fix must pass the **4-Domain Counterfactual Test** (generalizing across Wildlife, Ancient History, Dark Psychology, and Sci-Fi/Ocean Mysteries without domain-specific keywords in Python).
  2. **Backward Root-Cause Tracing & Right-Layer Defense-in-Depth**: Trace bugs backward from the symptom to the upstream source (`FFmpeg` ⬅ `VisualCritic/RAG` ⬅ `StockFetcher` ⬅ `VisualCurationAgent` ⬅ `Query Normalization` ⬅ `System Prompt`) and fix the root cause across all parallel flows (`HookVideoNode`, `VisualCurationAgent` batch & single scene, video & photo curation, and topic-agnostic CV/FFmpeg gates).
